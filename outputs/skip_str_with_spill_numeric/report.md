## Key Findings

1. **SkipStr+Spill is better than Original at low memory (256MB-4GB)**
   - At 256MB: Original is 9.2x slower, SkipStr+Spill is 3.4x slower
   - At 4GB: Original is 3.4x slower, SkipStr+Spill is 2.0x slower

2. **Both converge at high memory (10.5GB+)**
   - At 10.5GB: Original is 1.3x faster, SkipStr+Spill is similar
   - At 12.5GB: Original is 1.5x faster (all data in memory)

3. **For numeric-only queries**: SkipStr+Spill is dramatically better at low memory
   - At 256MB: Original 8.3x slower vs SkipStr+Spill 8.3x slower (same — both spill numerics)
   - At 4096MB: Original 1.7x slower vs SkipStr+Spill 2.5x slower

4. **For mixed queries**: SkipStr+Spill avoids the worst regressions
   - String columns read from Parquet (baseline speed) instead of slow disk cache
   - At 256MB: Original 9.4x slower vs SkipStr+Spill 2.6x slower

5. **Memory budget where performance equals baseline**: 10.5 GB (Original config, all columns in memory)
